This should be a living architectural description of the code we have:
- explain the current design;
- capture non-obvious behavior and invariants;
- give readers a map before they enter the implementation;
- evolve alongside the code whenever the design changes.

It is not an authority sitting above the implementation, not an approval gate,
and not a frozen contract against which development proceeds. Code and 
documentation describe the same evolving system; neither gets silently forced
to match stale text.
